# 1.5.1 — 로컬 AI 교정 하네스 보완

이전 실사용 형태 시험에서 올바른 수정안도 잘못된 근거 ID 때문에 누락됐고, 날짜가 여러 문장으로 나뉘며 JSON 응답이 잘리는 문제가 있었습니다. 모델이 작성해야 하는 내용을 줄이고 코드의 검증 범위를 넓혔습니다.

- 자유 수정안은 짧은 원문·수정문 한 쌍으로 제한합니다. 근거 표시는 코드가 검증하며 모델이 근거 ID를 지어내지 않습니다. 원문 위치, 숫자 보존, 허용 띄어쓰기를 검사하고 잘못된 응답은 한 번 재시도합니다.
- 날짜·소수·이메일·항목 번호는 문장 분할에서 보존합니다.
- `바람니다 → 바랍니다`는 기본 규칙입니다. 일부 부정 표현·자격 조사·경과 시간·목적 및 피동 문장은 원문과 수정된 전체 문장, 해당 규칙을 모델에 주고 검토시킵니다. 문맥 후보는 최대 세 개이며, AI 제안은 사용자 확인 후 적용합니다.
- 구조 검토에서 앞 항목이 해결되면 뒤 항목의 단계를 다시 계산합니다. 이미 규칙으로 해결된 항목은 모델에 재질문하지 않고 화면에 따로 집계합니다.

## 실제 모델 결과

동일한 Qwen3 0.6B Q4_K_M, CPU에서 시험했습니다. 다음 수치는 **기본 규칙과 수락한 AI 제안을 합친 결과**이며 모델 단독 정확도가 아닙니다. 정답을 모델 출력에 맞추어 바꾸지 않았습니다.

| 시험 | 이전 | 수정판 |
|---|---:|---:|
| 이전 오류 문장 15개 | 9개 교정 | 15개 교정 |
| 개발 중 비교한 고정 오류 문장 12개 | 1개 교정 | 12개 교정 |
| 연결된 글의 오류 7개 | 4개 교정 | 6개 교정 |
| 위 두 문장 세트의 정상 문장 26개 | 불필요한 수정 0 | 불필요한 수정 0 |

보완 후 별도로 만든 오류 12개·정상 12개에서는 **오류 7개 교정, 정상 문장 변경 0**이었습니다. 이 마지막 결과에 맞추어 엔진을 추가 조정하지 않았습니다. `끝난지 사흘`, `거두웠습니다`, `낼께요`, `했슴니다`, `의견을 찬성합니다`를 놓쳤습니다. 연결된 글의 `않 나갔습니다`도 보류했습니다. 의미 모순 예문은 탐지하지 못했습니다.

공문 4편은 기대 출력과 모두 일치했습니다. 필요한 AI 단계 10개는 모두 맞았고 단서 없는 3항목은 보류했으며, 불필요한 재검토 1항목은 규칙으로 해결했습니다. 실패·미검토 구간은 없었습니다.

시험 범위가 작은 합성 예문이므로 일반 문서 정확도를 보장하지 않습니다. 같은 모델의 재검토도 독립된 전문가 검수는 아닙니다.

코드 시험 672개와 소스·배포본 화면 시험 각각 28개가 통과했습니다. 배포본의 109개 코드·리소스가 소스와 일치하며, 실제 실행과 모델 직접 지정·CPU 추론·삭제도 검증했습니다.

## 파일과 재현

- 수치·남은 실패: [HARNESS-QUALITY-1.5.1.json](HARNESS-QUALITY-1.5.1.json)
- 문장별 정답·실제 출력·원시 응답: `_workspace/harness-quality-1.5.1/시험결과.html`, `baseline.json`, `current.json`, `unseen.json`
- 중간에 후보를 과도하게 보류했던 결과도 `intermediate-choice.json`에 보존했습니다.
- 실제 한글 검증: [HANCOM-STRUCTURE-1.5.1.json](HANCOM-STRUCTURE-1.5.1.json). 교정 공문, 자동 번호 6문단, 표 셀 문서를 경고 없이 열고 재저장한 뒤 본문·자동 번호 유지와 재검사 변경 0을 확인했습니다.
- 교정 공문: `_workspace/harness-quality-1.5.1/공문_교정결과.hwpx`. 원본과 교정본을 따로 저장했습니다. 한글에서 만든 미리보기와 XML 구조 검수도 확인했습니다.
- 로컬 설치 파일: `release/1.5.1/SsenDoc-Setup-1.5.1.exe`. 공개 게시나 기존 사용자 설치판 교체는 수행하지 않았습니다.

재현 명령은 `node scripts/test-harness-quality.cjs`, `node scripts/test-harness-quality.cjs --unseen`, `node scripts/report-harness-quality.cjs`입니다. 기준 버전 비교는 보존한 `_workspace/harness-baseline/src`가 있을 때 `--baseline`을 사용합니다. 한글 검증은 해당 프로그램과 이 PC의 파일 접근 모듈 등록이 필요합니다.
