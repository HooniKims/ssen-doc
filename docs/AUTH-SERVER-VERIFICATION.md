# 쎈doc 인증 서버 확인 — 2026-10-12

최종 1.1.0 패키지의 공통 인증 키트를 Electron에서 실행해 기존 PC의 이용권을 갱신했다. 메일 발송, 로그인, PC 등록·해제, 로그아웃은 수행하지 않았다. 요청·응답에서 앱 이름, 경로, HTTP 상태와 오류 코드만 확인했다. 이메일·계정 토큰·허가증 원문·기기 식별자는 이 기록에 포함하지 않는다.

## 서버 담당자 전달 내용

- 앱 내부 ID는 `doc`, 서버에 보내는 요청 본문의 앱 이름은 **`ssen-doc`**이다. 진단 정보의 제품 표시명 `SsenDoc`와 구분한다.
- 2026-10-12 **21:25:17 KST**에 `POST https://ssenbox.lovable.app/api/public/v1/license/token` 요청 본문으로 **`{"app":"ssen-doc"}`**를 실제 전송했다.
- 서버 응답은 **HTTP 200**이었다. `APP_NOT_ALLOWED` 등의 서버 오류 응답은 발생하지 않았다.
- 갱신 전 로컬 허가증 판정은 **`SCOPE`**였다. 이는 저장된 허가증의 `scope`에 `doc`가 없다는 클라이언트 검증 결과이며, 서버가 보낸 오류 코드가 아니다.
- 갱신된 허가증은 원본 키트의 서명·앱 권한 검증을 통과해 **`verdict: OK`, `canEdit: true`**가 됐다. 이 PC의 기존 공통 인증으로 쎈doc 권한 갱신이 가능함을 확인했다.
- 이번에 실제 실행한 작업은 **이용권 다시 확인(허가증 갱신)**이다. 신규 로그인이나 PC 재등록 요청은 보내지 않았다.

| 실제 요청 순서 | 메서드 | 경로 | 응답 |
|---|---|---|---|
| 1 | GET | `/keys` | 200 |
| 2 | POST | `/challenge` | 200 |
| 3 | POST | `/license/token` (`app: ssen-doc`) | 200, 허가증 검증 OK |
| 4 | GET | `/status` | 200 |

`인증 등록 대기중`이라는 문구 자체는 현재 앱·원본 키트 소스에서 확인되지 않았고 해당 화면을 재현하지는 않았다. 앞서 배포를 보류한 사유는 서버 지원 여부를 아직 확인하지 못했기 때문이다. 위 실응답으로 기존 PC의 `ssen-doc` 허가증 발급과 `doc` 권한 지원을 확인했다.

## 코드상 요청 구분과 남은 범위

- 로그인: `POST /auth/otp/verify`는 이메일·인증번호를 보낸다. 이후 상태 조회, PC 등록, 허가증 갱신을 순서대로 수행한다.
- PC 등록: `POST /devices/register`의 `app`은 `ssen-doc`이다. 이는 소스 및 모의 요청 테스트로 확인했으며 이번 실제 서버 확인에서 신규 등록은 실행하지 않았다.
- 허가증 갱신: `POST /license/token`의 `app`은 `ssen-doc`이고, 응답 토큰의 `scope`에는 짧은 이름 `doc`가 필요하다. 이번 실제 갱신으로 확인했다.
- 새로운 계정의 OTP 수신·신규 PC 등록·학교 업무망의 인증서/프록시·다른 쎈 앱의 로그아웃 전파는 별도 확인 대상이다.

동일 증상이 생기면 이용권 창에서 **이용권 다시 확인**을 누른 뒤 **인증 진단 정보**의 `lastFailure`와 `events`를 확인한다. 실패 경로 `stage`, 응답 `httpStatus`, 오류 `code`, 서버 추적값 `traceId`로 구분할 수 있다.
