# 쎈doc 검증 기록

## 1.1.0 공통 인증·선택형 AI — 2026-10-12

사용자 제공 인증 키트 1.0을 `app:'doc'`로 연결했다. 실제 계정에 인증번호를 보내거나 공통 저장소에서 로그아웃하지 않고, 별도 모의 인증으로 편집 권한을 시험했다. 실제 배포 EXE는 원본 인증 브리지로 열어 초기 화면과 로컬 검사를 확인했다.

## 설치·패키지·업데이트

첫 NSIS·ZIP 빌드는 생성됐으나 소스 변경과 빌드가 겹친 상태에서 내부 ASAR 손상을 발견했다. 이 산출물은 최종 검증 대상으로 사용하지 않는다. 최종 소스를 고정한 재빌드 뒤 `scripts/verify-package.cjs`로 소스와 묶음 파일 바이트를 대조한다. 최종 파일 해시·CPU 모듈·모델 제외 결과는 `PACKAGE-VERIFICATION.json`으로 기록한다.

최종 패키지·설치 실행 결과는 이 문서 하단에 추가한다. 실제 GitHub 상위 버전의 다운로드·교체 업데이트는 공개 릴리즈가 없어 검증하지 못했다. 업데이트 상태 전이·재시도·오류 처리·ZIP 분기는 모의 공급자 테스트를 통과했다. 릴리즈 정보가 없을 때 ‘최신 버전’이라고 잘못 표시하지 않는다.

배포판 UI 테스트에서 Playwright의 페이지 목록에 기존 보조 화면이 누락되는 현상을 확인했다. 배포판은 `scripts/test-packaged.cjs`에서 Electron의 실제 WebContents 화면에 입력·클릭 이벤트를 보내고 DOM 결과를 확인한다. 앱의 검사 IPC를 결과로 대체하지 않는다. 이 방식으로 일반 실행 설정에서 맞춤법·HTML 저장·대조 결과 6건·실제 HWPX 압축·세 화면 간 상태 유지·HTTP/HTTPS/WS/WSS 차단을 통과했다(`PACKAGED-UI-VERIFICATION.json`). 소스의 `npm run test:ui`는 Playwright locator로 6개 전체 흐름을 검증하고 `ui-*.png` 화면을 저장한다. 배포판의 기본 Electron 캡처가 빈 이미지를 반환해 해당 파일은 증거로 사용하지 않았다.

NSIS 실제 설치 후 자동 업데이트 모드를 확인하는 과정에서 `Uninstall SsenDoc.exe`를 한글 파일명으로 찾던 오류를 발견했다. 실제 파일명과 이전 한글 이름을 함께 인식하도록 수정하고 설치판·ZIP판·이전 이름 테스트를 추가했다.

## 최종 결과

- 단위 테스트 **564개**, 소스 UI 테스트 **6개** 통과. 배포판의 일반 설정에서도 세 기능 통합 검사 통과.
- 최종 NSIS·ZIP 빌드 성공. 묶음의 프로젝트 파일 **81개**를 원본과 바이트 단위로 대조해 일치 확인. CPU용 `win-x64` 네이티브 모듈만 포함하며 GGUF는 포함하지 않음.
- `SsenDoc-Setup-1.0.0.exe`: 184,360,178바이트. `SsenDoc-1.0.0-x64.zip`: 228,410,597바이트. SHA-256은 `PACKAGE-VERIFICATION.json`과 `release/SHA256SUMS.txt`에 기록.
- 최종 설치판을 `_workspace/install-test`에 실제 설치해 실행·맞춤법·띄어쓰기 교정을 확인. 자동 업데이트 모드가 `installed`로 인식됨. 실제 업데이트 확인은 배포 정보가 없어 오류 안내를 표시했으며 최신 버전으로 오인하지 않음.
- 테스트 설치 제거 종료 코드 0, 설치된 실행 파일 제거 확인. `INSTALL-VERIFICATION.json`. 기존 원본 앱과 사용자 문서는 수정하지 않음.
- 최종 무설치 `SsenDoc.exe`를 일반 실행으로 열어 Windows 화면과 접근성 트리를 확인. 세 메뉴·교정/저장 버튼·상시 하단 경고가 표시됨. 실제 창 캡처: `ui-packaged-live.jpg`. 확인 후 사용자가 바로 사용할 수 있도록 창을 열어 두었음.
- 실제 모델 다운로드·재개·추론·삭제·재다운로드·직접 지정은 개발판과 배포판에서 확인. 테스트 복사본 약 793MB는 정리했으며 `_workspace/ai-verification/models`의 검증용 원본 한 개는 재검증용으로 보관. 사용자 기본 프로필에는 모델을 강제로 설치하지 않음.

검증한 합성 문장·테스트 문서와 현재 Windows 장비에서 재현되는 실패를 수정한 결과다. 모든 문서의 정확도나 모든 PC의 호환성을 보장하는 기록은 아니다.

## 남은 한계

- 규칙과 사전은 전체 한국어를 판정하지 않는다. 고유명사·활용형·문맥·문장 전체 띄어쓰기는 누락·오탐이 있을 수 있다. 작은 AI도 잘못된 교정이나 누락을 낼 수 있다.
- 테스트 사례의 정확도는 임의의 학교 문서 정확도를 뜻하지 않는다. 모든 학교 서식을 시험하지 않았다.
- EXAONE는 라이선스 검토 중으로 비활성화했다. 권장 모델은 현재 사용 가능한 Qwen으로 고정되며 메모리 용량을 안내한다.
- HWPX·XLSX만 문서 교정 지원. 수식·필드·보호된 셀·일부 복잡한 문단은 읽기 전용. 한글/Excel에서 저장본을 실제로 열어 페이지 배치까지 확인하는 검증은 별도로 필요하다.
- 코드 서명·SmartScreen 평판 검증과 Windows 10 실제 장비 테스트는 하지 않았다. 현재 Windows 환경에서 실행했다.
- `npm audit --omit=dev`에서 운영 의존성 취약점 0개. 빌드 도구 체인에는 moderate 8개가 남아 있다. 공개 배포 전 패치 상황을 다시 확인한다.
- 로컬 검증 당시에는 공개 릴리즈가 없었다. 이후 게시와 확인 결과는 아래 기록을 따른다. 상위 버전으로 교체하는 실서비스 자동 업데이트는 아직 검증하지 않았다.

## 1.0.1 — Qwen 단일 모델 제공

- EXAONE 카탈로그 항목과 선택 불가 안내를 제거했다. 제공 모델은 Qwen3 0.6B Q4_K_M 한 가지이며 최초 다운로드 안내는 약 400MB로 수정했다. Qwen 파일명·주소·크기·SHA-256과 모델 관리·추론 로직은 그대로다.
- 단위 테스트 564개와 UI 테스트 6개를 다시 실행해 모두 통과했다. 모델 목록이 Qwen 한 개이며 선택되어 있는지, 약 400MB 안내, 직접 지정·삭제·재지정 흐름을 확인했다.
- 1.0.1 첫 화면 `ui-home.png`와 모델 관리 `ui-models.png`, 문서 교정·대조·압축 캡처를 새로 저장했다.
- 배포판 일반 실행 설정에서 맞춤법·띄어쓰기·복사·HTML 저장·문서 대조 6건·실제 HWPX 압축·화면 상태 유지·네트워크 차단 검증을 다시 통과했다.
- NSIS·ZIP 빌드 성공. 패키지 81개 파일과 소스 바이트 일치, 앱 버전 1.0.1, Qwen 단일 카탈로그, CPU 모듈만 포함, GGUF 미포함을 확인했다. `PACKAGE-VERIFICATION.json`.
- 1.0.1 NSIS를 테스트 경로에 설치해 맞춤법·띄어쓰기 교정, 설치형 업데이트 모드와 GitHub 조회 응답, 제거 성공을 확인했다. `INSTALL-VERIFICATION.json`. 상위 버전으로 실제 교체하는 업데이트 검증은 별도다.
- 실제 Qwen 다운로드·재개·CPU 추론의 전체 검증 기록은 같은 모델과 로직을 사용한 1.0.0 기록이다. 이번 변경으로 AI 정확도가 향상되었다고 주장하지 않는다.

## 1.0.2 — 이용약관 적용과 점검 수정

- 자체 이용약관 `LICENSE`를 적용했다. 설치 화면 약관 페이지(환영 다음, [동의함] 필요, 업데이트 설치 때는 건너뜀), 설치 폴더 `LICENSE.txt`, 설치본·실행 파일 LegalCopyright, 설정 · 업데이트 창의 저작권 줄과 [이용약관 보기]를 넣었다.
- 단위 테스트 570개, UI 테스트 7개(약관 펼침·닫힘 포함) 통과. `ui-license.png`.
- 빌드 후 패키지 78개 파일과 소스 바이트 일치, asar 안 `LICENSE`, 설치 폴더용 `LICENSE.txt`(UTF-16LE)와 원문 일치를 확인했다. `PACKAGE-VERIFICATION.json`.
- 설치본을 풀어 `LICENSE.txt`가 재료와 같음을 확인했다. 설치본과 `SsenDoc.exe`의 LegalCopyright는 `Copyright 2026 상명초 김승현, 등촌중 김형훈`이다. 게시자(CompanyName)는 기존 `HooniKim`을 유지했다.
- 실제 설치 화면에서 약관 페이지를 캡처했다. `ui-installer-license.png`.
- 배포판 실행에서 맞춤법·HTML 저장·문서 대조·HWPX 압축·약관 펼침/닫힘·네트워크 차단을 확인했다. `PACKAGED-UI-VERIFICATION.json`.
- 무인 설치 후 `LICENSE.txt` 설치, 맞춤법 교정, 업데이트 모드, 제거 시 `LICENSE.txt` 삭제를 확인했다. `INSTALL-VERIFICATION.json`.
- 공개 1.0.1 설치본(SHA-256 `0849a29e…`)을 설치한 위에 1.0.2를 덮어 설치해 버전 1.0.2, `LICENSE.txt`, 저작권 줄을 확인하고 제거했다.
- 시험 중 만든 이용자 결과물(TXT·HTML 교정문, HWPX·XLSX 교정본, 압축 HWPX 19개)에 앱 코드의 출처 표식이 들어가지 않았음을 확인했다.
- 공개 게시 후 5개 자산(설치형 EXE·ZIP·latest.yml·blockmap·SHA256SUMS.txt)의 다운로드 응답 200과 해시 일치를 확인했다. `RELEASE-PUBLICATION.json`.
- 공개 1.0.1을 설치해 앱 안 업데이트 확인을 실행했다. 1.0.2를 찾고, 내려받은 뒤 electron-updater의 SHA-512 확인을 통과해 "재시작하여 설치" 단계(ready)까지 진행됨을 확인했다. 재시작 후 실제 교체는 덮어 설치 시험으로 갈음했다.
