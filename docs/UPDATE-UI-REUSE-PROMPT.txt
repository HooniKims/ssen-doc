현재 프로젝트의 업데이트 UI를 쎈img와 같은 방식으로 실제 구현해 줘. 설명이나 시안만 만들지 말고, 기존 업데이트 기능에 연결하고 테스트까지 완료해 줘.

대상 앱은 현재 작업 폴더의 앱이다. 앱 이름·버전·프레임워크·배포 저장소·설정 파일·업데이트 방식을 코드에서 먼저 확인해 줘. 기존 구조와 디자인을 유지하면서 아래 요구사항을 적용해 줘. 쎈Doc·쎈img의 앱 이름이나 배포 주소를 대상 앱에 그대로 넣지 마.

1. 먼저 확인할 것
- 프로젝트 지침, 기존 업데이트 모듈, 앱 시작 코드, 제목 표시줄, 설정창, 사용자 설정 저장 방식, 업데이트 관련 테스트를 읽어 줘.
- 설치형 자동 업데이트와 ZIP/포터블 수동 교체가 구분되어 있는지 확인해 줘.
- 자동 확인 타이머가 구현되어 있어도 실제 앱 시작 경로에서 호출되는지 반드시 확인해 줘.
- 기존 업데이트 다운로드·서명/해시 검증·설치·재시작 확인 절차를 그대로 활용해 줘. UI 작업 때문에 다운로드와 설치를 별도 경로로 우회 구현하지 마.
- 참고 화면이 제공되어 있다면 실제로 보고, 알림 카드뿐 아니라 상세 업데이트 안내창까지 비교해 줘.

2. 제목 오른쪽 버전과 빨간점
- 앱 로고/제목 바로 오른쪽에 현재 실행 중인 앱 버전을 표시해 줘.
- 새 버전이 있으면 버전 글자의 오른쪽 위에 지름 약 8px의 작은 빨간점을 표시해 줘.
- 버전 영역 전체를 클릭 가능한 버튼으로 만들고, 클릭하면 상세 업데이트 안내창을 열어 줘.
- 마우스 툴팁과 접근성 이름에 현재 버전, 새 버전 유무, 업데이트 보기 동작을 설명해 줘. 빨간점 색만으로 상태를 전달하지 마.
- 키보드로 접근하고 Enter/Space로 열 수 있어야 하며, 제목 표시줄 드래그 영역과 클릭 영역이 충돌하면 안 돼.
- 최신 버전이거나 해당 버전을 건너뛰었으면 빨간점을 숨겨 줘.
- ‘나중에’는 알림 카드만 닫고 빨간점은 유지해 줘.

3. 오른쪽 아래 업데이트 알림 카드
- 새 안정 버전을 발견하면 현재 화면 오른쪽 아래에 비차단 알림 카드를 보여 줘. 문서 작업이나 입력을 가로막지 마.
- 기준 스타일: 너비 약 360px, 화면 오른쪽/아래 여백 약 24px, 흰색 배경, 옅은 테두리, 14px 안팎의 둥근 모서리, 은은한 그림자. 좁은 창에서는 화면 안에 맞춰 줘.
- 제목: ‘{앱 이름} {새 버전} 업데이트가 있어요’.
- 실제 릴리스의 주요 변경 내용을 글머리표 2~3개로 보여 줘. 개발자가 임의로 만든 예시 변경 내용을 제품에 고정하지 마.
- 실제 메타데이터에 파일 크기가 있으면 ‘설치 파일 약 175MB’ 또는 ‘ZIP 파일 약 218MB’처럼 표시해 줘.
- 전체 설치 파일 크기와 차등 업데이트 전송량을 혼동하지 마. 실제 차등 전송량이 확인되지 않았으면 ‘작은 파일 13MB만 받아요’ 같은 문구를 사용하지 마.
- 주요 버튼은 ‘업데이트’, 보조 버튼은 ‘나중에’, 텍스트 링크는 ‘이 버전 건너뛰기’. 오른쪽 위에는 닫기 X를 배치해 줘.
- 닫기 X와 ‘나중에’는 동일하게 카드만 닫아 줘.
- ZIP/포터블형은 주요 버튼을 ‘새 ZIP 받기’로 바꾸고 기존 공식 배포 페이지로 연결해 줘.
- 다운로드가 완료되면 제목은 유지하고 ‘다시 시작하면 적용돼요’ 안내와 ‘다시 시작해서 적용’ 버튼을 표시해 줘. 이 상태에서는 건너뛰기 링크를 숨겨 줘.
- 설치 준비 알림은 새 상태이므로, 다운로드 전 알림을 닫았더라도 한 번 안내할 수 있어야 해.

4. 상세 업데이트 안내창
- 제목은 ‘{앱 이름} 업데이트’, 오른쪽 위에는 닫기 X를 표시해 줘.
- 다음 순서로 구성해 줘.
  ① 지금 버전 / 상태 / 마지막 확인 시각의 세 줄 요약
  ② 실제 릴리스의 주요 변경 내용
  ③ 확인 가능한 실제 파일 크기 안내
  ④ 주요 업데이트 버튼과 ‘이 버전 건너뛰기’
  ⑤ 별도의 ‘지금 확인’ 버튼
  ⑥ ‘자동으로 확인하기’ 체크박스와 ‘시작 15초 뒤, 4시간마다’ 설명
  ⑦ 업데이트 확인 때 주고받는 정보 안내
- 상태는 확인 중, 최신 버전, 새 버전 있음, 다운로드 중, 설치 준비, 오류를 구분해 줘. 오류를 최신 버전으로 표시하면 안 돼.
- 마지막 확인 시각은 실제 확인 결과의 시각을 한국어 날짜/시간으로 표시하고, 확인 전에는 확인 전이라고 표시해 줘.
- 다운로드 진행률은 다운로드 중에만 보여 줘. 작업 중 중복 요청을 막아 줘.
- 업데이트 버튼을 주요 색상으로 강조하고, 수동 확인 버튼보다 우선 배치해 줘.
- 인터넷에 보내는 정보 안내는 실제 코드와 맞아야 해. 문서 내용이 전송되지 않는 앱이라면 ‘업데이트 확인 때는 버전 정보만 주고받아요. 문서 내용은 보내지 않아요.’처럼 표시해 줘.
- 기존 이용약관·제작자 정보 등 필요한 설정 기능의 접근성을 유지하되, 업데이트 안내보다 앞에서 시선을 분산시키지 않게 정리해 줘.
- Escape로 닫을 수 있고, 최소 지원 창 크기에서도 창과 버튼이 화면 밖으로 잘리지 않게 해 줘.

5. 알림과 설정의 동작 규칙
- 자동 확인은 기본 활성화하고, 실제 앱 시작 15초 뒤 첫 확인 및 이후 4시간마다 확인을 연결해 줘. 타이머를 중복 생성하지 마.
- 자동 확인을 끄면 예약된 확인을 중지하고 재실행 후에도 꺼진 상태를 유지해 줘. ‘지금 확인’ 수동 기능은 계속 제공해 줘.
- ‘나중에’로 닫은 같은 버전·같은 상태의 카드는 같은 실행 세션에서 반복 확인이나 화면 이동만으로 다시 나타나면 안 돼.
- ‘이 버전 건너뛰기’는 버전 단위로 사용자 설정에 저장하고, 앱 재실행 후에도 해당 버전의 카드와 빨간점을 숨겨 줘. 이후의 더 새 버전은 다시 알림을 보여 줘.
- 건너뛰기는 전체 업데이트 기능을 영구 해제하는 동작이 아니야. 사용자가 안내창에서 해당 업데이트를 직접 실행할 수 있어야 해.
- 설정을 디스크에 저장하지 못하면 성공한 것처럼 처리하지 말고 오류를 보여 줘. 이전 유효 설정을 유지해 줘.
- 여러 작업 화면/창에서 하나의 업데이트 상태와 설정을 공유해 줘. 화면마다 별도 확인 타이머나 서로 다른 건너뛰기 상태를 만들지 마.
- 이미 확인된 새 버전은 일시적 네트워크 오류가 났다고 지우지 마. 오류 상태와 재시도 방법을 안내해 줘.
- 개발 실행에서는 실제 업데이트 다운로드/설치를 실행하지 마. 테스트용 가짜 릴리스는 제품 코드에 활성화된 채 남기지 마.

6. 기존 업데이트 흐름과 연결
- 설치형은 자동 확인만 수행하며, 사용자가 ‘업데이트’를 눌렀을 때 다운로드하도록 해 줘. 자동 확인을 자동 설치로 바꾸지 마.
- 다운로드 완료만으로 앱을 종료하거나 재시작하지 마. 기존 작업 저장 여부 확인을 거쳐 사용자가 명시적으로 설치를 선택했을 때 재시작해 줘.
- 검사·변환·저장 등 실행 중인 작업과 충돌하는 설치는 기존 정책에 맞춰 차단해 줘.
- ZIP/포터블형에서는 설치형 자동 설치 엔진을 호출하지 마. 공식 배포 페이지를 통한 새 파일 받기를 안내해 줘.
- 배포 메타데이터의 임의 URL을 그대로 실행하지 말고, 기존의 신뢰할 수 있는 배포 주소 검증 규칙을 유지해 줘.
- 릴리스 노트는 신뢰할 수 없는 외부 문자열로 취급해 줘. HTML을 실행하지 말고 일반 텍스트로 렌더링하며 길이를 제한해 줘.
- Electron 앱이라면 기존 메인 프로세스 업데이트 모듈, preload API, IPC 허용 목록, 렌더러 공통 UI를 함께 점검해 줘. 다른 기술 스택이면 같은 책임 분리를 해당 구조에 맞춰 적용해 줘.

7. 반드시 검증할 시나리오
- 최신 버전/개발 실행: 카드와 빨간점 없음.
- 새 버전: 카드, 빨간점, 실제 변경 내용과 파일 크기 표시.
- 버전 클릭: 상세 안내창, 현재 버전, 상태, 마지막 확인 시각 표시.
- 나중에/X: 카드만 닫히고 빨간점 유지, 같은 세션에서 재확인해도 카드 반복 노출 없음.
- 건너뛰기: 같은 버전의 카드·빨간점 숨김, 설정 저장 및 재실행 후 유지, 더 새 버전은 다시 알림.
- 자동 확인: 15초 및 4시간 주기, 중복 시작 방지, 해제 후 타이머 중지, 설정 저장, 수동 확인 가능.
- 화면 이동: 모든 화면의 빨간점·카드·안내창·설정 상태 일치.
- 다운로드: 실제 상태 전이와 진행률 연결, 다운로드 완료 후 재시작 확인 전 설치 호출 없음.
- ZIP/포터블: 올바른 문구와 공식 배포 경로, 설치 엔진 호출 없음.
- 오류: 네트워크 실패·설정 저장 실패·다운로드 실패를 성공 또는 최신 상태로 오인하지 않음.
- 악성 HTML/긴 릴리스 노트: 스크립트/이미지 실행 없음, 화면 넘침 없음.
- 최소 창 크기와 일반 창 크기에서 실제 UI 스크린샷을 찍어 카드와 상세 안내창을 눈으로 확인.
- 기존 관련 테스트와 영향받는 화면의 회귀 테스트 실행.

8. 완료 보고
- 무엇을 구현했는지, 어떤 테스트가 몇 개 통과했는지, 아직 검증하지 않은 부분이 있는지 정확히 알려 줘.
- 실제 구현 화면의 ‘알림 카드 + 빨간점’과 ‘상세 업데이트 안내창’ 스크린샷을 남겨 줘.
- 테스트용 버전·가짜 서버를 썼다면 그 사실을 명시해 줘. 모의 테스트를 실제 공개 업데이트 다운로드나 배포 성공으로 표현하지 마.
- 소스 수정, 빌드 생성, 설치된 앱 반영, 공개 배포를 구분해 보고해 줘. 배포까지 요청받았다면 기존 배포 절차와 검증을 완료해 줘.
- 불필요한 전면 재설계나 별도 업데이트 시스템을 만들지 말고, 현재 앱에서 안정적으로 동작하는 완성된 변경을 남겨 줘.
